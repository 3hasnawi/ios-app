# خادم النسخ الاحتياطي لتطبيق الرواتب

إضافة Home Assistant OS تحفظ ملف التطبيق الكامل `نسخة الرواتب.zip` كما ينتجه `BackupActor`، من دون تحويله إلى أشهر أو رفع ملفات Excel يدوياً. يتضمن الملف الأشهر والرواتب والاستقطاعات والملاك والإعدادات، وتستطيع نسخة أخرى من التطبيق استرجاعه بعد موافقة المستخدم. ويمكن لتطبيق ويندوز مستقبلاً قراءة الملف نفسه وفق [العقد أدناه](#صيغة-النسخة-وتطبيق-ويندوز).

## التثبيت والتحديث

في Home Assistant: الإعدادات ← الإضافات ← متجر الإضافات ← قائمة النقاط الثلاث ← المستودعات؛ أضف `https://github.com/3hasnawi/ios-app`. حدّث الإضافة ذات المعرّف `salary_sync` إلى **0.2.0** وشغّلها. تغيّر اسمها الظاهر إلى «خادم النسخ الاحتياطي (تجريبي)» لكن المعرّف ثابت ليصلها التحديث بدلاً من إنشاء إضافة منفصلة. صفحة الإدارة داخل Home Assistant Ingress (8099). بيانات النموذج القديم في `snapshots.sqlite3` لا تتحول تلقائياً إلى نسخة احتياطية ولا تقرؤها الواجهة الجديدة.

يُظهر المنفذ الداخلي 8080 واجهة الأجهزة، وهو **غير منشور على المضيف افتراضياً**. لا تفتح هذا المنفذ على الإنترنت مباشرة. يحتاج الآيفون إلى عنوان HTTPS خاص وآمن يصل إلى 8080 (مثلاً عبر وكيل HTTPS داخل شبكة خاصة)، ثم يوضع عنوانه ورمز الجهاز في الإعدادات ← النسخ الاحتياطي. لا يُرسل ملف الرواتب عبر HTTP عادي. تأكد من وجود مساحة تكفي نسختين وملف رفع مؤقت؛ حجم الرفع الأقصى 512 MiB.

من واجهة الإضافة أنشئ رمز **كاتب** للآيفون الذي يرفع النسخ، ورمز **قارئ** لكل جهاز آخر. يظهر كل رمز مرة واحدة فقط؛ احفظه في مدير كلمات مرور. رمز القارئ لا يستطيع الرفع. إذا فُقد رمز أو كُشف، ألغِ رموز دوره من صفحة الإدارة وأنشئ رمزاً جديداً. يُحفظ رمز الآيفون في Keychain ولا يدخل الملف المرفوع. الإضافة تحتفظ بآخر نسختين للرجوع عند الحاجة، وتعرض آخر نسخة فقط للأجهزة. لا يحذف التحديث النسخ الموجودة.

عند نجاح الاستيراد ينشئ تطبيق الآيفون الملف ويرفعه تلقائياً. ويعيد المحاولة عند فتح التطبيق، ويجدد النسخة كل 24 ساعة عندما يعمل. لا يضمن iOS وقتاً ثابتاً لعملية نسخ والتطبيق مغلق. يستطيع جهاز قارئ تنزيل النسخة والتحقق من بصمتها، ثم يعرض التطبيق تأكيداً صريحاً قبل استبدال بياناته. اختيار «قارئ فقط» في إعدادات الجهاز الثاني يمنعه من رفع نسخة قديمة أو فارغة.

## واجهة الأجهزة

كل طلب بيانات يحتاج `Authorization: Bearer <token>` عبر HTTPS. يعمل رمز الكاتب للقراءة والكتابة، ورمز القارئ للقراءة فقط.

| الطلب | الوظيفة |
|---|---|
| `PUT /v1/backup` مع `Content-Type: application/zip` | يرفع ملف ZIP كاملاً برمز كاتب. الاستجابة تتضمن `revision`, `sha256`, `size`. |
| `GET /v1/backup/meta` | وصف آخر نسخة: تاريخ الرفع، البصمة، الحجم، الإصدار، أعداد الأشهر والرواتب والاستقطاعات والملاك. |
| `GET /v1/backup` | تنزيل ملف ZIP نفسه؛ رأس `ETag` يحوي SHA-256 للتحقق قبل الاسترجاع. |
| `GET /healthz` | فحص عمل الخدمة بلا بيانات شخصية. |

الرفع متدرج إلى ملف مؤقت، وتُفحص بنية ZIP وبصمات CRC وصيغة `manifest.json` قبل نشره. رفض الملف لا يغيّر النسخة الحالية. نسخة خالية تماماً لا تستبدل نسخة فيها بيانات. لا ترسل رموز الوصول أو ملفات حقيقية إلى GitHub أو سجلات الدعم.

## صيغة النسخة وتطبيق ويندوز

صيغة التطبيق الحالية `BackupFormat.version = 1`: ZIP يحوي `manifest.json`, `settings.json`, `months.jsonl`, `employees.jsonl`, `deductions.jsonl`, `staff.jsonl`. كل سطر JSON مستقل، وحقول Swift `Data` داخل JSON تُرمّز Base64؛ `createdAt` وحقول `Date` تُرمّز بالثواني منذ 2001-01-01 (افتراض `JSONEncoder`). يقرأ تطبيق ويندوز المستقبلي `GET /v1/backup`، يطابق SHA-256 مع `ETag`، ثم يفتح هذه الملفات للعرض. لا يحتاج إلى API منفصل لكل شهر. يجب على أي تطبيق يكتب النسخة المحافظة على هذا الإصدار أو نشر إصدار صيغة جديد بتوافق واضح.

قبل الاعتماد على بيانات الرواتب الفعلية: وفّر وصول HTTPS خاصاً، اختبر الرفع والتنزيل والاسترجاع ببيانات وهمية على الأجهزة، وخذ نسخة مشفرة خارج الـ mini PC وجرب استعادتها. ملفات `/data` تدخل نسخ Home Assistant الاحتياطية، لكن وجود نسخة خارجية يحمي من تلف قرص الجهاز.
